1.1 — Crear tablas en el Supabase del Hub

🗄️
Migración SQL — 4 tablas principales

Ejecutar en el SQL Editor del proyecto Supabase del hub.

-- Tabla 1: directorio de establecimientos CREATE TABLE stores ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), nombre TEXT NOT NULL, direccion TEXT, ciudad TEXT, lat DECIMAL(10,7), lng DECIMAL(10,7), activo BOOLEAN DEFAULT true, created_at TIMESTAMPTZ DEFAULT now() ); -- Tabla 2: catálogo agregado (snapshot de todas las tiendas) CREATE TABLE catalog_index ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), store_id UUID REFERENCES stores(id) ON DELETE CASCADE, producto_nombre TEXT NOT NULL, marca TEXT, precio INTEGER, stock_disponible INTEGER DEFAULT 0, imagen_url TEXT, ultima_sync TIMESTAMPTZ DEFAULT now(), searchable TSVECTOR GENERATED ALWAYS AS ( to_tsvector('spanish', coalesce(producto_nombre,'') || ' ' || coalesce(marca,'')) ) STORED ); CREATE INDEX idx_catalog_fts ON catalog_index USING GIN(searchable); CREATE INDEX idx_catalog_store ON catalog_index(store_id); CREATE INDEX idx_catalog_marca ON catalog_index(marca); -- Tabla 3: identidad global del cliente (1 registro por RUT) CREATE TABLE customers ( id UUID PRIMARY KEY DEFAULT gen_random_uuid(), rut TEXT UNIQUE NOT NULL, nombre TEXT, email TEXT, telefono TEXT, push_token TEXT, -- Expo push token para notificaciones created_at TIMESTAMPTZ DEFAULT now() ); -- Tabla 4: historial cross-store (base del ranking personalizado) CREATE TABLE customer_store_history ( customer_id UUID REFERENCES customers(id) ON DELETE CASCADE, store_id UUID REFERENCES stores(id) ON DELETE CASCADE, total_compras INTEGER DEFAULT 0, monto_historico BIGINT DEFAULT 0, ultima_compra DATE, PRIMARY KEY (customer_id, store_id) );

1.2 — Crear el proyecto Next.js del Hub (API)

⚙️
Nuevo proyecto Next.js separado de la app de tiendas

El hub es una API independiente. Puede ser un proyecto Next.js nuevo, o Hono si se prefiere algo más ligero. Los endpoints que necesita implementar son:

POST /api/auth/rut GET /api/search GET /api/stores GET /api/me POST /api/sync/catalog POST /api/sync/purchase
🔍
Implementar GET /api/search — el endpoint más crítico

Recibe: q (texto), lat, lng, customer_id (opcional). Devuelve productos rankeados según fidelidad, distancia y precio.

// Hub: src/app/api/search/route.ts export async function GET(req: NextRequest) { const q = req.nextUrl.searchParams.get("q") ?? ""; const lat = parseFloat(req.nextUrl.searchParams.get("lat") ?? "0"); const lng = parseFloat(req.nextUrl.searchParams.get("lng") ?? "0"); const customerId = req.nextUrl.searchParams.get("customer_id"); // 1. Búsqueda Full Text Search en catalog_index const { data: results } = await supabase .from("catalog_index") .select("*, stores(id, nombre, lat, lng, direccion)") .textSearch("searchable", q, { type: "plain", config: "spanish" }) .gt("stock_disponible", 0); // 2. Obtener historial del cliente (si está autenticado) let history: Record<string, number> = {}; if (customerId) { const { data: h } = await supabase .from("customer_store_history") .select("store_id, total_compras") .eq("customer_id", customerId); history = Object.fromEntries((h ?? []).map(r => [r.store_id, r.total_compras])); } // 3. Calcular distancia y aplicar ranking const ranked = (results ?? []) .map(r => { const store = r.stores as { lat: number; lng: number; id: string } | null; const dist = store ? haversine(lat, lng, store.lat, store.lng) : 9999; const fidelidad = history[r.store_id] ?? 0; return { ...r, distancia_km: dist, fidelidad }; }) .sort((a, b) => { if (a.fidelidad !== b.fidelidad) return b.fidelidad - a.fidelidad; if (Math.abs(a.distancia_km - b.distancia_km) > 1) return a.distancia_km - b.distancia_km; return (a.precio ?? 0) - (b.precio ?? 0); }); return NextResponse.json(ranked); }
🔐
Implementar POST /api/auth/rut — autenticación por RUT

Valida el RUT (algoritmo módulo 11), busca o crea el cliente en la tabla customers, devuelve un JWT firmado.

// Validación dígito verificador chileno function validarRUT(rut: string): boolean { const clean = rut.replace(/[.\-]/g, ""); const body = clean.slice(0, -1); const dv = clean.slice(-1).toUpperCase(); let sum = 0, mul = 2; for (let i = body.length - 1; i >= 0; i--) { sum += parseInt(body[i]) * mul; mul = mul === 7 ? 2 : mul + 1; } const expected = 11 - (sum % 11); const dvCalc = expected === 11 ? "0" : expected === 10 ? "K" : String(expected); return dv === dvCalc; } // POST /api/auth/rut export async function POST(req: NextRequest) { const { rut, nombre, email } = await req.json(); if (!validarRUT(rut)) return NextResponse.json({ error: "RUT inválido" }, { status: 400 }); // Buscar o crear cliente const { data: existing } = await supabase.from("customers").select("id").eq("rut", rut).single(); const customerId = existing?.id ?? (await supabase.from("customers") .insert({ rut, nombre, email }).select("id").single()).data?.id; // Generar JWT (30 días) const token = jwt.sign({ sub: customerId, rut }, process.env.JWT_SECRET!, { expiresIn: "30d" }); return NextResponse.json({ token, customer_id: customerId }); }

Implementar POST /api/sync/catalog y POST /api/sync/purchase

Endpoints que reciben datos de los stores. Autenticados con el HUB_SYNC_SECRET del store.

// POST /api/sync/catalog — recibe lista de productos de un store // Hace UPSERT en catalog_index basado en (store_id, producto_nombre) export async function POST(req: NextRequest) { const secret = req.headers.get("authorization")?.replace("Bearer ", ""); const { data: store } = await supabase.from("stores").select("id").eq("sync_secret", secret).single(); if (!store) return NextResponse.json({ error: "Unauthorized" }, { status: 401 }); const { productos } = await req.json(); await supabase.from("catalog_index").upsert( productos.map((p: Product) => ({ store_id: store.id, ...p, ultima_sync: new Date().toISOString() })), { onConflict: "store_id,producto_nombre" } ); return NextResponse.json({ ok: true, synced: productos.length }); } // POST /api/sync/purchase — registra una venta y actualiza historial del cliente export async function POST(req: NextRequest) { const { customer_rut, monto } = await req.json(); // Buscar/crear cliente, luego incrementar customer_store_history // ... }

Semana 4 · Mínimos cambios en la app web actual
📝
Registrar el primer store en el hub

Crear un registro en la tabla stores del hub con el nombre, dirección y coordenadas del establecimiento. Guardar el store_id y el sync_secret generado.

🔧
Agregar sync de catálogo a la app web (endpoint interno)

Crear un route handler en la app web existente que el store llama periódicamente (o que se llama automáticamente al cambiar productos).

// Agregar en la app web del store: src/app/api/hub-sync/catalog/route.ts export async function POST() { if (!process.env.HUB_URL) return Response.json({ ok: true, skipped: true }); const supabase = createServiceClient(); const { data: productos } = await supabase .from("productos") .select("nombre, marca, precio, stock, imagen_url") .eq("activo", true); const res = await fetch(`${process.env.HUB_URL}/api/sync/catalog`, { method: "POST", headers: { "Content-Type": "application/json", "Authorization": `Bearer ${process.env.HUB_SYNC_SECRET}`, }, body: JSON.stringify({ productos }), }); return Response.json({ ok: res.ok }); }

3.2 — Funcionalidades core (Semanas 6–7)

🏠
Pantalla Home

Saludo personalizado, búsqueda rápida, carrusel de mascotas, sección "Tus tiendas", alertas de alimento por agotarse.

🔍
Pantalla de Búsqueda + Resultados

Llamada a GET /api/search con texto + coordenadas GPS. Cards de resultado con foto, nombre, precio, tienda y distancia. Badge "Compraste aquí" para tiendas con historial. Filtros por marca, precio y distancia.

🏪
Pantalla de Detalle de Tienda

Nombre, dirección, mini mapa, listado de productos del store, historial del cliente en esa tienda.

🐾
Pantalla de Mascotas

Listado de mascotas del cliente con foto, nombre y especie. Por cada mascota, mostrar productos asociados con días estimados de alimento restante. Botón "Re-buscar este alimento".

3.3 — Funcionalidades secundarias (Semanas 8–9)

🗺️
Pantalla de Mapa

Todos los stores activos en un mapa con react-native-maps. Pin del usuario. Tap en un store → card preview con CTA a detalle.

👤
Pantalla de Perfil

Datos del cliente, historial de compras cross-store en timeline, resumen de lealtad por tienda, preferencias de notificaciones.

🔔
Push Notifications

Registro del Expo push token en el hub al hacer login. Notificaciones para alertas de consumo (alimento por agotarse). Fallback con notificaciones locales programadas.

📶
Modo offline

Últimos resultados de búsqueda persistidos en AsyncStorage. Banner visible cuando no hay conexión. Mascotas y tiendas favoritas accesibles sin internet.

QA, Lanzamiento y Monitoreo
Semanas 10–12 · Testing, stores y métricas
🧪
Testing end-to-end con múltiples stores

Conectar al menos 2 stores reales al hub. Verificar que la búsqueda devuelve resultados de ambos, que el ranking es correcto, y que los precios están actualizados.

Pruebas de performance

El endpoint de búsqueda debe responder en menos de 2 segundos en conexión 4G. Probar con 10+ stores en el hub para validar que el FTS escala.
